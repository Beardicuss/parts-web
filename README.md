# Parts Catalog

Каталог автозапчастей: публичная часть с поиском/фильтрами (код, марка, категория)
и закрытая админ-панель для добавления/редактирования/удаления позиций.
Без корзины и оплаты — чистый каталог.

- Языки интерфейса: EN / KA (переключатель в шапке)
- Стек: **React + Vite** (весь сайт) + **Supabase** (база данных, хранилище фото, логин админа)
- **Своего сервера нет.** Это осознанное решение: после сдачи проекта никто не должен
  администрировать бэкенд, патчить ОС или следить, не упал ли процесс. Всё, что обычно
  делает backend, тут делает Supabase — управляемый сервис с автоматическими бэкапами.

## Структура

```
frontend/           React SPA: публичный каталог + /admin панель
supabase/schema.sql  SQL-скрипт: таблицы, права доступа, storage bucket для фото
```

## Разовая настройка (делаешь один раз при сдаче проекта)

### 1. Создать проект в Supabase

1. Зайди на [supabase.com](https://supabase.com), создай бесплатный аккаунт и новый проект
   (лучше сразу на почту/аккаунт клиента — так он останется владельцем после сдачи)
2. Дождись, пока проект поднимется (1-2 минуты)

### 2. Накатить схему базы данных

1. В панели Supabase открой **SQL Editor** → **New query**
2. Скопируй содержимое файла `supabase/schema.sql` из этого репозитория, вставь и нажми **Run**
3. Это создаст таблицы `parts`, `brands`, `categories`, права доступа (публичное чтение,
   запись только для авторизованных) и storage bucket `part-images` для фото

### 3. Создать аккаунт админа

1. **Authentication** → **Users** → **Add user** → **Create new user**
2. Укажи email и пароль клиента — это и есть логин в `/admin`
3. Зайди в **Authentication** → **Providers** → **Email** и отключи **"Allow new users to sign up"**,
   чтобы никто посторонний не мог сам себе создать доступ к админке

### 4. Достать ключи для frontend

**Project Settings** → **API** — скопируй:
- `Project URL`
- `anon public` ключ (НЕ `service_role` — тот секретный и не должен попасть на клиент)

## Запуск (разработка)

```bash
cd frontend
npm install
cp .env.example .env
```

Впиши в `.env` значения `Project URL` и `anon public` ключ из шага выше:

```
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-public-key
```

Запуск:

```bash
npm run dev
```

- Публичный каталог: `http://localhost:5173/`
- Админка: `http://localhost:5173/admin/login` (email/пароль из шага 3)

## Продакшн: деплой на Cloudflare Pages

```bash
cd frontend
npm run build
```

1. В Cloudflare Pages создай проект, подключи репозиторий (или загрузи `frontend/dist` вручную)
2. Build command: `npm run build`, output directory: `frontend/dist`
3. В настройках проекта → **Environment variables** добавь те же `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY`
4. Готово — сайт живёт на статике Cloudflare, данные — в Supabase. Обслуживать нечего.

## Кто что может (RLS-права)

- **Любой посетитель сайта** — только читает каталог (`SELECT`), ничего не может изменить,
  даже зная технические детали — это обеспечено политиками Row Level Security в базе,
  а не только фронтендом
- **Авторизованный админ** (единственный аккаунт, созданный в шаге 3) — может добавлять,
  редактировать, удалять запчасти, бренды, категории и фото

## Стоимость на постоянку

- Cloudflare Pages — $0 (статический хостинг, безлимитный трафик)
- Supabase free tier — $0 (хватает с большим запасом для каталога такого размера:
  500MB базы, 1GB хранилища фото, 50 000 запросов auth/мес)
- Домен — отдельная стоимость, регистрируется на клиента

Итого: **$0/мес** пока проект не перерастёт бесплатные лимиты — а перерастёт нескоро.
